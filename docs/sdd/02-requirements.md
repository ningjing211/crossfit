# 02 需求與 Acceptance Criteria

規格以 `docs/prd/PRD.md` 為準。2026-10-08 已確認平台分工與資料模型。

## 已確認的 Acceptance Criteria

1. 能呈現一堂課。一筆紀錄有上課日，以及零到多個區塊。
2. 區塊有標題。Warm-Up、Movement Prep、EMOM10 都只是標題文字，不是寫死的三種型別。
3. 區塊可以有一段訓練方式說明（例如 Every Minute on the Minute for 10 Minutes，以及剩餘時間休息）。
4. 區塊內的每一項至少有動作名稱，並可記下組數、頻率與時間、速度、這一項的備註。
5. 左右次數（5/5、3/3）寫在該項備註，不另開欄位。
6. 動作本體能記下名稱、一張圖片、一支影片、施作要點、施作方式。圖片與影片可以沒有。
7. 一堂課能記下學生感受、老師感受、地點、器材、天氣。五個欄位都可以是空字串，空字串仍是一堂有效的課。
8. 不提供重量、次數最大值、帳號、推播、聊天、約課、付款。
9. 沒有對外 HTTP `/api`。瀏覽器與 App 不呼叫自建 REST。

## 平台

10. Web 與 Mobile 都只呈現課表、動作、已有的圖片與影片。
11. 日記五個欄位有文字才顯示。沒有填寫或儲存控制。
12. 介面沒有新增、編輯、刪除、上傳。
13. 開發者改 `catalog.ts` 來增減內容。

## 仍然不做

- 老師或學生使用的新增、編輯
- 登入、角色、多位選手
- 把部署用的 Firestore 或 Storage rules 改成允許讀寫，以及 `firebase deploy`
- Callable、Trigger、排程
- 左右次數的獨立欄位
- 一個動作多張圖或多支影片
- 圖片與影片的大小、長度上限
- 刪除整堂課或整個動作
- 每週自動產生下一堂課
